# Changelog

> **In short:** major changes to `@nuxt-layers/profile`, newest first. Formal releases are suspended during development (ADR-0008); consumers follow `master`.

## 2026-11-09

- Wording sweep (no behaviour change): every comment and document now describes Profile in its own terms (the host's directory, sign-in service and access decision, and the SemanticPresentationTheme capability), naming no other layer except where the architecture requires it (`capability.json`, suite membership in the README, `RESOURCES.md`, released migrations).
- **Breaking: Profile knows no other layer** (contract version 2). It describes everything in its own terms; the host translates.
  - Request parts: Profile names only its own part, `profile`. The host declares every other part in `composeProfile({ requestParts: { parts, defaults } })`: which are `coordinated` (answered through `requestCoordinator`), which are `holdable`, at most one `directory` part (settled by Profile's commands), and the parts each request type gets by default. Requests, holds and `recordProfileRequestPart` are validated against the declaration. `REQUEST_PARTS`, `COORDINATED_PARTS`, `LEGAL_HOLD_PARTS`, `DEFAULT_REQUEST_PARTS`, `CoordinatedPart` and `LegalHoldPart` are removed; `PROFILE_REQUEST_PART`, `requestPartSchema`, `REQUEST_PART_PATTERN`, `MAX_REQUEST_PARTS`, `requestPartsDeclarationSchema`, `resolveProfileRequestParts`, `orderRequestParts`, `ProfileRequestPartsDeclaration` and `ProfileRequestParts` are added; `RequestPart` is now a string. Migration `0006_host_declared_parts` replaces the fixed lists in the `request_part.part` and `legal_hold.parts` checks with the part-name grammar, so every stored value stays valid and readable.
  - Events in: `applyProfileIdentityEvent`, `IdentityEventLike` and `IDENTITY_EVENTS_HANDLED` are removed. Profile's own idempotent commands replace them, each taking `commandId` and `correlationId`: `provisionProfileRecord`, `recordProfileDeparture`, `closeProfileSubject`, `recordProfilePause`, `recordProfileGroupRenamed` and `disposeProfileGroup` (schemas exported from `./contracts`). Behaviour, idempotency, hold handling and outbox writes are unchanged.
  - Ports: `ProfileDisclosureContextPort`, `ProfileSubject` (with `PROFILE_ASSURANCE_LEVELS`), their enums, `ProfileRequestCoordinator` (`part` is now any declared coordinated part) and `PROFILE_PERMISSIONS` are restated in Profile's terms, with the same structure: existing disclosure-context, subject-resolver and access-decision adapters still fit.
  - Composition: declaring a coordinated part without `requestCoordinator` now fails composition; an access request with no coordinated part no longer needs the coordination port.
  - Presentation: the four other parts' names are gone from `presentation/messages.ts`; a host words its parts with `profile.requests.part.<name>`, and any it does not word reads "Another part of your account".
  - **Migrating a host:** (1) pass `requestParts` declaring the parts it used to rely on, for example `{ parts: [{ name: 'identity', coordinated: true, directory: true }, { name: 'authentication', coordinated: true, holdable: true }, { name: 'authorisation', coordinated: true, holdable: true }, { name: 'configuration', coordinated: true }], defaults: { erasure: ['identity', 'authentication', 'authorisation'] } }` keeps the old names and behaviour; (2) replace each `applyProfileIdentityEvent(event)` call with the command for that event (`identity.provisioned` of a person → `provisionProfileRecord`, `membership.ended` → `recordProfileDeparture` with `endedAt: event.occurredAt`, `identity.closed` → `closeProfileSubject`, `identity.paused` → `recordProfilePause`, `group.renamed` → `recordProfileGroupRenamed`, `group.deleted` with disposal due or `group.disposal-due` → `disposeProfileGroup`), passing `commandId: event.eventId` so that already-processed events stay duplicates; (3) word the declared parts in `profile.messages` if the defaults' wording was shown; (4) import `RequestPart` in place of `CoordinatedPart` and `LegalHoldPart`.
- `createProfileTestPorts()` (and `@nuxt-layers/profile/testing`): stand-ins for every port but the database, refused outside tests unless a demonstration opts in; the minimal host uses them. `profileTasks()`: Profile's scheduled work in ADR-0012's shape. Both additions. The gaps between Profile's caller, access and mail ports and ADR-0012's shared shapes are recorded in the specification (§18).
- Dependency review allows no advisories: the simple-git, braces and node-forge exceptions no longer match anything installed, and the `@simple-git/argv-parser` override is gone with simple-git. glob 14.0.2 and minimatch 11.0.1 are forced by override (GHSA-3g3m-2fjr-6pw4, GHSA-g3hv-75wg-m249) until nitropack's dependencies accept them.
- Development toolchain moves to the ADR-0013 baseline: Node.js 26, pnpm 12.16.1 through Corepack, `@types/node` 26 and Nuxt 4.6.3 for development; `zod` ^4.6.7. Hosts' requirements are unchanged (Node.js 22 or later, `nuxt` ^4.5.0).
- CI sets pnpm up with Corepack instead of a third-party action (ADR-0013 §5). The layer workflow had not started since the move to `nuxt-layers`, most likely because the organisation's Actions policy refuses that action.
- Theme Manager is declared as `github:nuxt-layers/theme-manager#master`; pnpm 12 records it as an HTTPS Git resolution.

## 2026-11-08

- `composeProfile(composition)` is now the only way to compose Profile (ADR-0012 §1): one call, all or nothing, then migrations. **Breaking:** the `provide*` functions and `migrateProfileDatabase()` are no longer public; a host passes the same ports under `database`, `keyWrapper`, `disclosureContext`, `subjectResolver` (optional), `requestCoordinator`, `accessDecision`, `notifier`, `clock` and `retention`. New type `ProfileComposition` in `./contracts`.
- `examples/minimal-host`: the smallest host composing Profile alone (ADR-0012 §4), built and smoke-tested in CI against PostgreSQL, and held to the 50-line composition budget by `tests/minimal-host.test.ts`.
- Moved from the `nuxt4-layers` organisation to `nuxt-layers`: the package is now `@nuxt-layers/profile` (formerly `@nuxt4-layers/profile`), and the repository `nuxt-layers/profile`. Hosts change their dependency to `git+https://github.com/nuxt-layers/profile.git#master` and every `@nuxt4-layers/profile` import, `extends` entry and stylesheet import to `@nuxt-layers/profile`. No API, runtime key, environment variable, schema or event changes.
- Theme Manager (development only) now follows `nuxt-layers/theme-manager` on `master`.
- Root `CONTRACT.md`, `RESOURCES.md`, `PLAN.md` (formerly `docs/roadmap.md`) and `STORAGE-REGISTER.md`; `docs/composition-contract.md` folded into `CONTRACT.md`. External links now appear only in `RESOURCES.md`.
- Versioning follows ADR-0008: the semantic-versioning promise is withdrawn while releases are suspended, and the existing `v1.0.0` and `v1.1.0` tags remain historical records, not consumer pins. Contract version 1 is unchanged.

## Before the move (tag `v1.1.0`)

- Access requests gain a `configuration` part: the configuration layer's settings for the person's own account, answered through the coordination port like another member's part, and `null` where the host composes no configuration layer. `REQUEST_PARTS` and `COORDINATED_PARTS` gain the value, with migration `0005_configuration_part`; erasure requests are unchanged, since the configuration layer deletes those settings itself on closure. An addition: hosts' coordination ports answer the new part through iam-integration's `profileRequestCoordinatorFromMembers`.
- The layer's own tests pass on Windows as well as on Linux and macOS: the paths they compare with import specifiers and routes are written with `/` on every platform (`tests/support/paths.ts`). On Windows the contract, architecture and endpoint tests used to fail, or check nothing.

## 1.0.0 (2026-10-11, tag `v1.0.0`)

Everything in contract version 1 ([specification](docs/contracts.md)).

- The person's record under their control: every value encrypted with their own key, wrapped by the host's key service, with key rotation.
- Disclosure chosen by the person, the departure data policy, display-name lookups and contact-detail verification.
- Data-subject requests, legal holds, erasure on closure, export, end of life and retention.
- The `/api/profile/*` endpoints and the accessible default pages, including `ProfilePersonName`.
