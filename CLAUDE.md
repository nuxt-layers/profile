# @nuxt-layers/profile — notes for Claude

## What this is
Nuxt foundation layer (built on Nuxt 4) for the personal data that describes a person (what is held, who may see it, how it is anonymised), under the person's control. A member of the IAM suite (ADR-0005). Governed by `nuxt-layers/architecture-rules` (revision reviewed in `RESOURCES.md`); persistence follows ADR-0002 and ADR-0006. Profile names no other layer: the host composes it with the others and translates between them. British spelling everywhere, including code and the manifest.

## Commands
- Toolchain (ADR-0013): Node.js 26, pnpm 12 through Corepack (`corepack enable`; version from `packageManager`), TypeScript 6. CI installs Corepack and uses no third-party setup action. Hosts need Node.js 26.13 or later (`engines`), because Clock, a runtime dependency, needs native `Temporal`; raise it only when a runtime dependency requires it, never merely to match the development baseline
- `pnpm install`, then `pnpm dev:prepare` for Nuxt types. Never add a `prepare`/`postinstall` script: Git installs would then pull devDependencies into hosts
- `pnpm check` = `nuxt typecheck` + `vitest run`; run it after every code change
- `pnpm build:playground` proves the layer composes in a host
- `examples/minimal-host` composes Profile alone within ADR-0012's 50-line budget (`tests/minimal-host.test.ts`, part of `pnpm check`); `pnpm build:minimal-host` then `pnpm smoke:minimal-host` (needs `PROFILE_TEST_DATABASE_URL`). Keep it minimal: stand-ins only where another capability would answer
- Single test file: `pnpm vitest run tests/<name>.test.ts`
- `tests/database.test.ts` and `tests/http.test.ts` need `PROFILE_TEST_DATABASE_URL` (admin URL of a local, disposable PostgreSQL 16). They skip locally without it and fail in CI
- Never edit a released migration in `server/database/migrations.ts`; add a new one
- `python3 scripts/check_markdown.py` (the architecture's own check) checks headings, *In short* lines under `docs/`, local links, and that external links appear only in `RESOURCES.md`, pinned; run it after every documentation change
- Browser tests: `pnpm test:e2e` (builds the playground, then Playwright with axe). Needs `PROFILE_TEST_DATABASE_URL`; locally set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if Playwright's own browser is not installed
- Clock (`@nuxt-layers/clock`) is a runtime dependency on `github:nuxt-layers/clock#master`, and the layer extends it (Layer Standard §5). Every date and time goes through Clock: server code through `server/internal/clock.ts` (`profileTime`), presentation through `useClock()`. Never use `Date` arithmetic, `Date.now()`, `toISOString()` or `toLocale*String()` for Profile's own times. `ProfileClock` is Clock's `ClockPort`, `{ now(): string }`. A gap in Clock (such as zone-name validation) is raised with Clock, not worked around further
- Theme Manager follows `github:nuxt-layers/theme-manager#master` (ADR-0008: dependencies on other layers track `master`, never a tag or commit). The lockfile records the resolved commit over HTTPS (pnpm 12 writes `repo: https://github.com/...`), never `git@github.com` (CI has no SSH key); refresh it when Theme Manager's `master` moves

## Rules
- Profile is the only canonical source of the data that describes a person. Never store sign-in identifiers, credentials, groups, memberships or permissions here: they are Authentication's, Identity's and Authorisation's.
- Contract (`contracts/`, `shared/`) imports only zod. No Nuxt, Vue, h3, server code, drivers, key services or other `@nuxt-layers/*` packages (Clock included: date and time work belongs on the server or in presentation). Enforced by `tests/contracts.test.ts`.
- Public surface: package root, `./contracts`, `./capability`, `composeProfile` (the only way to compose, type `ProfileComposition`; its `clock` is optional, Clock's system clock without it, `retention` too, the defaults without it, and `requestParts`, Profile's own part only without it), `createLocalProfileKeyWrapper`, `createProfileTestPorts` (and `./testing`; refused unless `NODE_ENV` is `test` or `{ demonstration: true }`), `profileTasks`, `getOwnProfile`, `updateProfile`, `setProfileDisclosure`, `anonymiseProfileDeparture`, `lookupProfileDisplayNames`, `viewProfile`, `exportProfileData`, the commands (`provisionProfileRecord`, `recordProfileDeparture`, `closeProfileSubject`, `recordProfilePause`, `recordProfileGroupRenamed`, `disposeProfileGroup`), `eraseProfile`, `rewrapProfileKeys`, `profileKeyVersionsInUse`, `relayProfileOutbox`, `consumeProfileLookup`, `listProfileDepartures`, the request and legal-hold functions (`openProfileRequest`, `listProfileRequests`, `getProfileRequest`, `getProfileRequestArchive`, `settleProfileRequestPart`, `recordProfileRequestPart`, `placeProfileLegalHold`, `releaseProfileLegalHold`, `listProfileLegalHolds`, `profileLegalHoldParts`, `runProfileMaintenance`), `startProfileContactVerification`, `confirmProfileContactVerification`, the `/api/profile/*` endpoints, `useProfile()`, `./presentation`, `./tailwind.css`, the default pages, the `Profile*` components (`ProfilePersonName` among them) and `useProfileText()`, `useProfileAction()`, `useProfileRoutes()`, `useProfileNames()`, `forgetProfileNames()`. `server/internal` (including the per-port composition registry) and `server/database` are private. Never re-expose per-port `provide*` functions.
- Members never import one another, and Profile knows none of them: it states every port, command and request part in its own terms, and the host translates. The host's directory reaches Profile through the disclosure-context port and Profile's commands; the only request part Profile names is `profile` (the host declares the rest in `composeProfile`'s `requestParts`).
- Every attribute value, and every kept departure name, is encrypted with the person's own key before it reaches the database, with the identity and purpose bound as additional data. Data keys are stored only wrapped by the host's `ProfileKeyWrapper`. Never store or log a value in plaintext. Keep `tests/database.test.ts` proving it.
- Erasure deletes the record, departures and wrapped key, and records the identifier as erased; no record is ever recreated for it. Key rotation re-wraps live keys only. Keep the rotation and erasure test.
- Disclosure: the person chooses each attribute's audience; secure defaults (name to group, all else to nobody). Standing comes from the host's directory, through the disclosure-context port, at every lookup, never cached. Hidden answers look the same whether or not a person or record exists.
- The caller passes `subjectId` and `viewerId` from the signed-in principal, never from a request body.
- Endpoints (`server/api/profile/`) take the subject only from `requireSubject` (the host's resolver); parse bodies with strict schemas through `readJson`; call the server functions, never SQL; and are wrapped in `profileHandler`. Export and contact-detail changes need `requireRecentSignIn`; lookups count against the rate limit; changes carry `expectedVersion`. `tests/http.test.ts` mounts every file, so a new endpoint is tested by being added. Never add an erasure endpoint: erasure follows account closure.
- `useProfile()` is for the user experience only and decides nothing.
- Presentation (`presentation/`, `modules/presentation.ts`) imports only the contract (plus Clock's auto-imported `useClock()` for dates) and reaches the server only through `useProfile()`; never `$fetch` or `/api/`. It decides nothing and offers no erasure. Text comes from `presentation/messages.ts` via `useProfileText()`. Style only through the SemanticPresentationTheme vocabulary (`profileClasses`), never raw colours or Tailwind default sizes; any cross-role pairing goes in `DELIBERATE_PAIRINGS` (`presentation/pairings.ts`) and `docs/contracts.md` §13. Never weaken an axe or contrast assertion to get green. Names are looked up in the browser only, and never put in a document title.
- Events and logs carry identifiers, attribute names and codes only. Requests, parts and legal holds too; any request bundle is sealed with the person's key.
- Operators' functions (requests of any type, settling parts, legal holds) are server-only: never an endpoint. A legal hold defers erasure only; a held closed record is read by no function.
- Verification codes are stored only as keyed digests bound to the value; Profile sends nothing to a contact detail but a code the person asked for.
- Required ports fail closed. No implicit in-memory store and no default key.
- Defaults are secure; loosening a default needs a documented risk treatment.
- Keep `CONTRACT.md` (the host's only document, ADR-0012 §6), `docs/contracts.md`, `docs/threat-model.md` (control register), `STORAGE-REGISTER.md` and `PLAN.md` in step with code. External links appear only in `RESOURCES.md`, pinned to the commit reviewed; other documents refer to its entries.
- No formal releases or tags while ADR-0008 suspends them; `CHANGELOG.md` records major changes by date.
- Platform-agnostic: the layer and its tests run alike on Windows, macOS and Linux. Tests that compare file paths with import specifiers or routes pass them through `toPosix` (`tests/support/paths.ts`) first: Node's path functions answer with `\` on Windows.
- Package manager: pnpm. Commit `pnpm-lock.yaml`.
